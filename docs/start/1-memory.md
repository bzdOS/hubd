# 1. Memory — an agent that remembers the project

**What you get.** A card per project that says where it stands, a journal of what
was decided and why, and one call that puts both back into an agent's context after
a compaction, a crash or a night away. No other setup: one folder, one agent.

Ten minutes. Every output below is real, captured on a node called `oak`.

## A practice hub

Everything in these tutorials happens in a practice hub, so nothing lands in your
real one:

```bash
npm i -g @bzdos/hubd
export HUBD_DIR=/tmp/hub-tour HUBD_TEAM_DIR=/tmp/hub-tour HUBD_NODE=oak
hub version
```

```text
hubd 0.9.56
  running:  …/@bzdos/hubd/hub/cli.mjs
  node:     v24.16.0
  hub base: /tmp/hub-tour
```

`HUBD_DIR` moves the hub; `HUBD_TEAM_DIR` moves the queues and presence with it.
`HUBD_NODE` names this machine in the hub (by default, its hostname); calling it
`oak` here makes the ids you get match the ones below. Drop the exports and the
same commands use `~/.hubd`, for real. A hub is a folder
of markdown and JSONL: at any step you can `cat` what just happened.

```bash
hub init "$HUBD_DIR"
```

```text
scaffolding a team folder in /tmp/hub-tour
  created AGENTS.md
  created INBOX.md
  created queues/README.md
  created specs/SPEC_template.md
  created .gitignore

Next steps:
  Connect an agent:  claude mcp add --scope user hubd --env HUBD_AGENT=dev-<project> --env HUBD_DIR=/tmp/hub-tour --env HUBD_TEAM_DIR=/tmp/hub-tour --env HUBD_NODE=oak -- npx -y @bzdos/hubd
                     (name HUBD_AGENT for the function the agent performs, not the model)
  Or, checked:       hub setup --harness claude|gemini|opencode|omp|dsh --agent dev-<project>
  Check setup:       hub doctor
  Full org template: hubd-company/ in the hubd repository
```

The connect line carries the variables this shell set, so an agent connected with it
uses this hub, not `~/.hubd`; this tutorial connects one [below](#connect-the-agent).
`AGENTS.md` is your team's constitution, yours to write; hubd never touches it.
`HUBD.md`, which appears beside it on the first run, is the manual for agents,
regenerated by every version: never edit that one.

## A project gets a card

A project is a folder; its slug is the folder's name. Here is one, with one commit
and one file not yet committed:

```bash
mkdir -p /tmp/hub-tour-work/shop && cd /tmp/hub-tour-work/shop
git init -q && echo '# shop' > README.md && git add -A && git commit -qm "a shop"
echo draft > pay.md
hub sync . -m "A small web shop. Checkout works end to end on staging; card payments are next." --agent dev-shop
```

```text
Synced: shop → /tmp/hub-tour/projects/shop.md
```

`-m` is the digest: what is true now, in a few lines. `--agent` is who says so:
name the function (`dev-shop`), not the model. This is the call your agent will
make as `hub_sync`; hubd reads the branch, the commits and the dirty count from
git itself, so nobody retypes what git already knows.

```bash
hub status
```

```text
slug                      synced                open  digest
──────────────────────────────────────────────────────────────────────────────────────────
shop                      2026-10-07 12:53 by … 0     A small web shop. Checkout works end to
```

## A report, at the moment of the finding

A session says what it learned in prefix-tagged lines, and each line goes to its
place:

```bash
hub report -p shop --agent dev-shop <<'EOF'
DECIDE: take card payments through a hosted payment page | no card data on our servers
FACT: staging checkout times out after 30 s on carts of 50+ items
NEXT: wire the hosted payment page into checkout
EOF
```

```text
Reported to shop: 1 decision, 1 fact, next set
```

The card is now this (`cat /tmp/hub-tour/projects/shop.md`, abridged):

```text
# shop

- slug: shop
- set: 2026-10-07 12:53 by dev-shop

## Digest

A small web shop. Checkout works end to end on staging; card payments are next.

## Next step

- wire the hosted payment page into checkout — set 2026-10-07 12:53 by dev-shop

## Facts & hypotheses

- fact: staging checkout times out after 30 s on carts of 50+ items

## Decisions

- 2026-10-07 12:53: take card payments through a hosted payment page — no card data on our servers

## Facts (auto)
…
- branch: master · uncommitted: 1 · last commit: 2026-10-07 12:53:03 +0000
```

A decision is an event as well as state, so it also goes to the journal:

```bash
hub log shop
```

```text
2026-10-08 15:36 [shop/dev-shop] sync: synced with digest [card Digest, Facts (auto): 797 B, new]
2026-10-08 15:36 [shop/dev-shop] decision: take card payments through a hosted payment page — no card data on our servers [card Decisions, Facts & hypotheses, Next step: 906 B, +109]
```

The bracket is what each write left the card at: the sections it touched, the card's
size in bytes, and the change. If the card ever reads older than a write you made, the
journal says which write shrank it; git is not needed for that.

Write `FACT:` when you find it, not at the end. A session whose context is compacted
never reaches "the end", and the finding leaves with the context.

[section] shop card / Next step  as of 2026-10-07 12:53

Every hit says where it lives and how old it is, so a stale answer looks stale.

## After a compaction

This is what memory is for. Inside the project folder:

```bash
hub whereami
```

```text
project:  shop  via path   root /tmp/hub-tour-work/shop
digest:   set 2026-10-08 15:36 by dev-shop (0d ago)
  A small web shop. Checkout works end to end on staging; card payments are next.
tasks:    0 open
claims:   none
here:     nobody else heartbeating under this root
journal:
  2026-10-08 15:36 [dev-shop] sync: synced with digest [card Digest, Facts (auto): 797 B, new]
  2026-10-08 15:36 [dev-shop] decision: take card payments through a hosted payment page — no card data on our servers [card Decisions, Facts & hypotheses, Next step: 906 B, +109]
git:      master  clean
  bde1637 a shop
  untracked (does it already exist?):
    pay.md  draft
  changed in the last 30 min:
    README.md
    pay.md
```

State, not a summary of a conversation: the digest and its age, the open work, who
else is in this checkout, what was decided, and what git says changed. The untracked
file is listed with its first line, because a session that lost its context is about
to write that file again.

## Connect the agent

Give the agent the same hub, and a name:

```bash
claude mcp add hubd-tour --env HUBD_AGENT=dev-shop --env HUBD_DIR=/tmp/hub-tour --env HUBD_TEAM_DIR=/tmp/hub-tour --env HUBD_NODE=oak -- npx -y @bzdos/hubd
```

`hub setup --harness claude --agent dev-shop --hub /tmp/hub-tour` does it too, as `hubd`,
and starts the server first to see it answer; it knows Gemini CLI, opencode, oh-my-pi
and dsh as well. Any MCP client that can run `npx -y @bzdos/hubd` over stdio works
the same; a client without MCP pastes a block from [prompts/](../../prompts/README.md). Restart the
client in the project folder and tell it:

> Call hub_context with your cwd.

What comes back is the same state, as data:

```json
{
 "project": "shop",
 "via": "path",
 "root": "/tmp/hub-tour-work/shop",
 "guessed": false,
 "digest": "A small web shop. Checkout works end to end on staging; card payments are next.",
 "digestSetAt": "2026-10-07 12:53",
 "digestSetBy": "dev-shop",
 "digestAgeDays": 0,
 "laws": [],
 "openTasks": [],
 "activeClaims": [],
 "presenceHere": [],
 "journalTail": [ … ]
}
```

From here the agent keeps the card itself: `hub_report` as it finds things,
`hub_sync` when the state moves, `hub_context` first after every compaction. The
protocol the server hands it (`hub_onboarding`, the same text as `HUBD.md`) tells it
so; you do not have to.

If the folder's name is not the slug you want, put the slug in a file called `.hubd`
at the project's root, one line, and the guess becomes certain.

## What hubd refuses here, and why

**A model as the author.** The journal is forever, and many sessions share a model's name.

```bash
hub sync . -m "x" --agent claude
```

```text
Error: agent "claude" names a model, a client or a placeholder, not a session — many sessions share it, so nothing can tell them apart later. Name the function you perform: "dev-<project>", "reviewer-<project>". Which model you are is read from the transcript, not from here.
```

**No author at all.** Every write names who made it.

```bash
hub sync . -m "x"
```

```text
Error: --agent required (or set HUBD_AGENT): the function doing this, e.g. "dev-hubd"
```

Over MCP the floor is softer: a call that forgets the author is attributed to
`HUBD_AGENT` plus a short per-session suffix rather than lost. Set `HUBD_AGENT` on
day one.

**An event written into the snapshot.** A card is what is true now; a dated line is
what makes it stop being one.

```bash
hub card shop --append-line "2026-10-07 hosted payment page wired" --by dev-shop
```

```text
Error: appendLine starts with a date, so it is an event, not state: file it with hub_report (FACT: / DECIDE: / COMM:), which writes the right card section AND the journal. A card is the snapshot — "what is true now" — and a dated line is what makes it stop being one.
```

The same rule caps a digest (8 KB by default, `card.digestBytes` in the hub's
`limits.json`) and moves a section's oldest lines into `projects/history/<slug>.md`
when it outgrows its own cap. Moved, never dropped: the card is their only copy.
